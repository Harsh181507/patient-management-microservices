What happens behind the scenes

  1. Login → POST :4004/auth/login. The API Gateway forwards to auth-service, which checks the BCrypt password in its Postgres DB and returns a signed JWT.
  2. Every patient call carries Authorization: Bearer <jwt>. The gateway's JwtValidation filter asks auth-service /validate first; a bad token gets 401.
  3. patient-service (Spring Boot + Postgres) handles CRUD at /api/patients.
  4. Creating a patient also calls billing-service over gRPC (port 9001) to open a billing account…
  5. …and publishes a Protobuf event to Kafka topic patient, consumed by analytics-service (see its logs).
